# Elephant-foot hull experiment

This page starts with the **complete Corner Bracket**. Only after the
problem is visible on the real model do we zoom into one arm tip and inspect
the two elephant-foot hull surfaces.

The question is:

> Can the four small arm-tip corrections be absorbed into the same two
> hull surfaces that already create the main elephant-foot relief?

The production model can be tested directly with:

```openscad
ef_corner_correction = true;
```

Set it to `false` to disable **only** the four small arm-tip corrections.
The two main `inside_relief_envelope()` hulls remain active.

## 1. First verify the complete bracket

Before looking at hull input surfaces, establish exactly what already works.

### 1A. Complete bracket — only the two main EF hulls

This is the real printable bracket with:

- the normal L profile;
- the outside `cs` side chamfers;
- nut pockets and bolt holes;
- both main `inside_relief_envelope()` hulls;
- **no** `relief_corner_miters()`.

![Complete bracket with only the two main elephant-foot hulls](../design/efh_00_whole_main_only.png)

This is also what you get in the real model when:

```openscad
ef_corner_correction = false;
```

Most of the elephant-foot relief is already correct. The remaining problem
is local to the places where the EF relief reaches an arm end.

### 1B. The four problem locations on the complete bracket

The same bracket is shown again with **four red location markers**:

![Complete bracket with the four problem locations marked](../design/efh_00_whole_problem_points.png)

The red spheres are deliberately just markers, **not the correction
geometry itself**. Their only purpose is to make the four tiny junctions
visible at whole-bracket scale.

There are four because the bracket has:

- two arm ends; and
- two print-facing Y sides.

So this establishes the starting point:

> The main two-hull elephant-foot construction works over the long contact
> edges and inside radius. The unresolved geometry is concentrated at the
> four arm-tip / side-chamfer junctions.

The **exact missing relief volume** is shown later in section 3A, after
we zoom into one of these marked locations.

### 1C. Complete working bracket — correction enabled

Now enable the current correction:

```openscad
ef_corner_correction = true;
```

![Complete working bracket with the corner correction enabled](../design/efh_00_whole_working.png)

This is the production reference. The rest of this page asks whether the
difference between 1A and 1C can be generated by reshaping only the two
existing EF hull surfaces.

## 2. How one main EF hull is built

Now zoom into **one horizontal arm end on the +Y print side**.

The sequence deliberately mirrors the outside `cs` hull walkthrough:

**source profile → surface A → surface B → both surfaces → hull → result**

### 2A. Source relief profile

The elephant-foot relief is made by **subtracting material from the two
wood-contact faces** of the bracket. We therefore do not hull the bracket
itself. We first make a 2D **relief profile** on the wood side of those
faces.

In the X/Z side view:

- the horizontal wood-contact face lies along `z = 0`;
- the vertical wood-contact face lies along `x = 0`;
- the relief profile occupies the open area at **x ≥ 0 and z ≤ 0**;
- at the inside corner, its boundary follows the same `r_in` curve as the
  bracket.

So `inside_opening_2d()` is simply the large 2D shape immediately
**inside the L**, touching both wood-contact edges. It extends beyond the
arm ends on purpose; only the part that overlaps the bracket can remove
material.

![2D relief profile beside the two wood-contact faces](../design/efh_01_opening_profile.png)

```openscad
module inside_opening_2d() {
    reach = max(5, cs + ef + 1);

    difference() {
        translate([0, -armV - reach])
            square([armH + reach, armV + reach]);

        if (r_in > 0)
            inside_corner_2d(r_in);
    }
}
```

The important point is: **this blue shape is the relief profile used to build the hull; it is not part of the bracket**.

### 2B. First hull surface — Y = 9.4 mm

The first thin surface uses the unchanged opening:

![First EF hull surface](../design/efh_02_inner_main_input.png)

```openscad
opening_layer(W/2 - ef);
```

With the defaults `W=20` and `ef=0.6`, this is Y=9.4 mm.

### 2C. Second hull surface — Y = 10.0 mm

The second surface lies on the print face and expands the opening by
`ef=0.6`:

![Second EF hull surface](../design/efh_03_outer_main_input.png)

```openscad

```

### 2D. Both hull surfaces together

These are the only two children passed to the main `hull()` on this side:

![Both EF hull surfaces](../design/efh_04_both_main_inputs.png)

Blue is the unchanged opening at Y=9.4; orange is the expanded opening at
Y=10.0.

### 2E. Resulting hull

![Main EF hull](../design/efh_05_main_hull.png)

### 2F. Result after subtracting the main hull

![Result with only the main EF hull](../design/efh_06_main_result.png)

## 4. Test the strongest two-surface version

Instead of guessing a new tip polygon, take the **exact cross-sections of
the working relief volume itself** at the same two Y positions.

## 5. Measured result

CI renders the same local experiment as STL and measures the relief
volumes:

| `cs` | `ef` | Reference | Two-surface candidate | XOR | Overcut | Undercut | Missing tip before correction |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2.0 | 0.6 | 1.2433 | 2.4922 | 1.9006 | 1.5743 | 0.3263 | 0.3772 |
| 3.0 | 1.2 | 6.0395 | 9.1928 | 6.3398 | 4.7466 | 1.5932 | 2.0005 |
| 2.0 | 0.3 | 0.3101 | 0.8152 | 0.7139 | 0.6095 | 0.1044 | 0.1108 |

Volumes are mm³ and apply only to the cropped horizontal arm-tip region.

The test therefore says something narrower than “a hull solution is
impossible”:

> **Using only two hull surfaces at the existing Y positions does not
> reproduce the current working arm-tip geometry, even when those two
> surfaces are exact sections of the working relief volume.**

A different construction with more Y sections or a different decomposition
would be a different experiment.
